# MVC → Service → DDD 学习计划

从工程分层到领域驱动设计的系统性学习路径。

## 学习阶段

### 第一阶段：MVC → Service 层

重点是理解分层职责，学会写出职责单一、可维护的代码。

| 书目 | 作者 | 说明 |
|------|------|------|
| 《Spring in Action》 | Craig Walls | 最经典的 Spring 入门，讲清楚 Controller / Service / Repository 各层边界 |
| 《Clean Code》 | Robert C. Martin | 不绑定框架，讲如何写出职责单一的代码，是理解"为什么要分层"的底层逻辑 |

---

### 第二阶段：DDD 入门

DDD 原著很厚，不建议一上来就啃。按精华 → 实践的顺序推进。

| 书目 | 作者 | 说明 |
|------|------|------|
| 《Domain-Driven Design Distilled》 | Vaughn Vernon | DDD 精华提炼版，薄、直接、实践导向，目前最好的入门书 |
| 《实现领域驱动设计》（红皮书） | Vaughn Vernon | 入门之后的进阶，有大量代码示例，讲聚合、仓储、应用服务如何落地 |

---

### 第三阶段：融会贯通

把分层、领域建模与架构设计串联起来。

| 书目 | 作者 | 说明 |
|------|------|------|
| 《Clean Architecture》 | Robert C. Martin | 将分层、依赖方向、领域隔离讲得很系统，是 DDD 落地的架构基础 |
| 《领域驱动设计》（蓝皮书） | Eric Evans | DDD 的原始出处，概念权威但偏抽象，建议放在最后读，用来校准理解 |

---

## 推荐顺序

```text
Clean Code
 ↓
Spring in Action（边做项目边看）
 ↓
DDD Distilled
 ↓
实现领域驱动设计
 ↓
Clean Architecture
 ↓
DDD 蓝皮书（选读）
```

---

## 实践建议

光看书容易忘。建议找一个真实的业务场景（比如一个简单的订单系统），从 MVC 开始写，主动把它重构到 Service 层，再重构到 DDD，亲手踩一遍坑，比看十遍书有效。
